# 编码规范

- 先遵循目标项目的语言、分层、命名和错误处理习惯；只在降低重复或明确职责时抽取方法和模块，脚本无需照搬服务端分层。
- 注释解释不明显的原因、约束和取舍，不逐行复述代码。
- 按排障需要记录结果、耗时、错误和关联标识；参数只记录必要且已脱敏字段，不打印密码、令牌、Cookie 或完整敏感请求响应。
- 优先复用项目已有依赖与组件；确需新增依赖时评估维护、兼容性和复杂度，不因存在开源包就引入。
- 修改后运行与改动路径严格对应的检查：纯原型或文档（`prototypes/`、`docs/`）仅执行 `pnpm proto:check`，严禁触发后端测试或生产构建；涉及正式前端（`frontend/src/`）执行 `pnpm build`；涉及后端（`internal/`、`*.go`）执行 `go test`。不为无行为变化的整理堆叠测试。失败先定位原因，在任务范围内修复并复验。
