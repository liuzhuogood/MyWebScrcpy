# 全局模板匹配服务

模板匹配服务用于调试，调试时按需启动。正式执行任务时，由任务脚本负责模板匹配。

在「系统配置 → 模板匹配」点击「检测依赖」，环境可用后点击「启动」。Go 启动和重启不会自动运行匹配进程。服务运行时，一个 Python 进程负责所有当前投屏设备；关闭投屏或禁用该设备全部模板后，对应匹配任务在下一轮设备检查时退出。没有投屏设备时总服务仍运行，设备数为 0。

需在实际配置的 Python 3.10+ 中安装本版 mywebscrcpy-sdk 与 httpx、websocket-client、av、opencv-python-headless 和 numpy。使用 SDK 源码时，可将下面的 python3 替换为检测显示的解释器路径：

```sh
python3 -m pip install './packages/python-sdk[vision]'
```

系统配置的 Python 卡片支持通过 pip 安装已发布的同版本 SDK 与识图依赖。本次源码新增的 Vision 能力需要按上面的命令安装本仓库 SDK；PyPI 上已发布的同版本基础包不包含这些新增能力，正式发布时需更新 VERSION。服务不自动安装这些依赖。依赖不完整时不能启动，检测显示缺少的模块。修改 Python 路径后需停止服务再检测，启动也会重新检查。

模板启用且算法受 SDK 支持时，匹配结果通过现有 Vision 接口发布，播放器的匹配框开关继续生效。当前 SDK 支持主图片、TM_CCOEFF_NORMED、阈值、灰度与缩放；多参考图片与其他算法仍按 SDK 能力限制处理。运行中不代表一定命中，静止画面没有新帧时显示「等待画面」。自动服务只识别，不点击或执行 ADB。

模板管理中可直接进入系统配置启动服务；独立 SDK/旧 CLI 发布结果的入口继续可用。进程异常退出时显示错误，需要手动重新启动。

接口：GET `/api/matching-service/status`；POST `/api/matching-service/check`、`/start`、`/stop`。完整路径和响应结构见应用 API 文档。停止会清理匹配连接和进程，超过退出期限才强制结束本次服务的进程。
