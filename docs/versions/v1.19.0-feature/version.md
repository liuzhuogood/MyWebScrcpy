# v1.19.0-feature 版本说明：投屏启动加速与会话并发优化

日期：2026-10-11。状态：正式实现与真机性能验证完成。

1. 在 `scrcpy-server` 启动参数中显式设置 `cleanup=false`，阻止设备端 `CleanUp` 子进程自动删除 `/data/local/tmp/scrcpy-server.jar`，使 Jar 包在设备端持久保留。
2. 按设备缓存 Android SDK 版本与 `scrcpy-server.jar` 就绪状态；首次连接通过单次 `adb shell` 合并探测 SDK 与远端 Jar 大小，匹配时直接跳过 715KB 重复推送，同进程后续冷启动零额外探测开销。
3. 保留异常自愈能力：跳过 Jar 推送后若握手失败（如设备重启清空临时目录导致进程秒退），自动强制重推 Jar 并重试建连。
4. 移除 `Server.Push` 中多余的 `adb shell ls -la` 校验与 `startSession` 中硬编码的 `1500ms` 死等，改为 `40ms` 初始等待配合 `50ms/100ms` 自适应快速握手探测及进程退出即时感知。
5. 将会话启动锁从 `Hub` 全局互斥细化为按 `serial` 单飞建连（Per-Serial Singleflight），消除多设备同屏或单台慢设备对其他设备投屏的串行阻塞。
6. 将会话空闲保活时间从 10 秒延长至 60 秒，提升页面切换时的关键帧热复用命中率。

真机（`10.0.0.244:5555`）实测端到端首帧耗时：首次免推冷启动从 `2,664ms` 降至 `888ms`（提速 `3.00x`），同进程重复冷启动从平均 `2,194ms` 降至平均 `644ms`、最快 `534ms`（提速 `3.41x ~ 3.90x`），60 秒保活期内重连 `< 1ms`。证据见 [设计文档](design.md#性能测试与真机对比证据)。
