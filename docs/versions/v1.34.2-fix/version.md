## 已确认原因与交互取舍

GUI 当时处于实时“手机视图”。原代码只允许 `viewMode === 'deck'` 进入框选，`DashTile` 画布接收触控事件；卡片标题或显式开窗按钮可触发开窗，不能代表整卡点击链路已符合用户期望。按用户明确设计，首页卡片现在用于拖动框选、单击开窗，到小窗/详情页中直接操控手机。

`DashTile.interactive` 默认 `true`，仅首页传 `false`，其他消费场景仍保持原输入行为；共享群控接收通道保留。框选限定在本卡片容器，排除勾选按钮，卸载清理监听与延迟任务；Mock 可预览选择，但不打开真实设备投屏。

旧页面同时使用视口最小高度、按 `window.innerHeight` 计算的容器最小高度、两层底部留白；旧顶栏还处于带溢出属性的页面容器中。新主页使用固定视口外壳和独立 `overflow-y-auto` 内容区，顶栏不进入内容滚动；不靠隐藏设备内容来掩盖溢出。
