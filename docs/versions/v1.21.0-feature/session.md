# v1.21.0-feature 会话记录：Pi 技能生成 Python

## 2026-10-12：检查与方案讨论

**用户**：「看一下现在的 Markdown 生成 Python 脚本的时候有利用 Pi agent 吗？」

**Codex**：检查当前调用链。右侧文档助手通过 Pi RPC 修改 Markdown；「生成 Python」和执行前自动编译调用本地 Go 编译器。生成代码中的「Pi Engine」只是固定字符串。普通步骤只打印、等待，设备与模板匹配方法仍是占位实现，不能据此认定真实自动化可用。

**用户**：「设计一下，怎么让 Pi 参与脚本生成，我的设想是创建一个 Pi 技能来做这件事，在技能里告诉 Pi 怎么转换，生成什么样子的脚本。」

**Codex**：建议创建项目专用 `markdown-to-python` 技能。Pi 依据冻结文档、任务配置、真实模板资料和运行接口说明生成 Python；后端校验、保存，现有任务系统执行。生成阶段只读资料，不试运行手机动作。提供稳定的 Python 运行库，避免每次生成设备通信代码或复制占位实现。复用现有活动展示，不新增独立工作台。

**Codex**：建议运行与定时执行使用已校验产物，文档或接口变化后重新生成；旧生成器的去留、执行前自动编译的调整需要在实施前确认。模板匹配尚未接入任务运行接口，先评估已有独立 Python 工程，不把资产管理 API 当作匹配服务。

### 当前核对依据

- `internal/mdscript/handlers.go`：编译请求直接调用 `Compiler.Compile`。
- `internal/mdscript/compiler.go`：本地拼接 Python，设备及匹配方法为占位实现。
- `internal/mdscript/executor.go`：手动和定时执行共享执行器，需要时自动编译。
- `internal/taskmanager/manager.go`：按目标设备独立启动 Python，已有超时、终止、日志及任务记录。
- `internal/aiprovider/pi.go`：已有独立临时目录、只读工具、流式事件和进程清理；提示词固定为文档助手，不能直接当生成入口使用。
- `internal/pibundle/bundle.go`：技能随包释放，已有技能文件不覆盖；新增技能与后续升级规则需区分。
- `main_desktop.go`、`internal/desktop/server.go`：桌面服务使用动态监听地址，运行库不能硬编码端口。
