# v1.12.0-feature 设计说明：Web 端重构

## 版本定位

将独立 Vue Web 前端并入 `MyWebScrcpy`，直接替换旧 HTML 前端，统一源码、构建、静态资源与部署。重构主体已完成并部署，当前收口重点为三个遗留问题。

原显示尺寸入设置、手机边框和录制反馈设计保留在 [延期方案](deferred-plan.md)，尚未实施。

## 当前结构与入口

- `frontend/`：Vue、TypeScript、Vite 前端，主要页面与业务组件使用现有 shadcn-vue 组件。
- `web/dist/`：前端构建产物，由 Go 嵌入二进制。
- `scripts/build.sh`：先构建前端，再构建 Go 程序。
- `.github/workflows/release.yml`：标签发布任务调用统一构建，提交本身不触发该发布流程；新工作流运行尚未验收。
- `/`、`/player`、`/dashboard`、`/files`：新页面入口；旧 `/app/` 与旧 HTML 页面返回 404。
- 后端业务 API、WebSocket、`/api-docs.html` 与 `/api/openapi.json` 保留。

## 遗留问题与处理方向

### 1. 分割线总是占不满

用户反馈投屏与侧栏之间的分割线未覆盖工作区全高。共享布局位于 `frontend/src/components/layout/SplitLayout.vue`；现有代码含高度与 Grid 设置，但尚未复现用户场景，不能据此推断具体原因。

处理时核对页面容器、共享布局、主画面、分割线和侧栏的高度关系。优先在共享布局修正，避免为每个侧栏重复添加补丁。

验收覆盖检查、文件、终端、模板、回放和设置面板的打开与切换，以及拖拽、窗口缩放、横竖屏与全屏；窄屏按现有上下布局检查，不强制显示竖向分割线。

### 2. 图标未统一

当前业务组件主要从 `lucide-vue-next` 导入图标，部分基础组件从 `@lucide/vue` 导入，依赖中两者并存。来源混用是已确认事实；具体视觉差异仍需逐页核对。

统一使用已有的 `lucide-vue-next` 入口，核对首页、播放器、大屏、文件管理和侧栏。同一动作使用同一图标；尺寸、线宽、按钮内对齐和交互状态按现有组件规范统一。清理另一依赖前确认所有引用已迁移；保留可访问名称，不新增开发说明文案。

### 3. 模板匹配功能当前不可用

后端 `internal/template/handler.go` 当前只注册模板资产管理接口；v1.11 已移除内嵌匹配与自动点击。前端 `frontend/src/api/templates.ts` 仍请求 `/api/templates/matches` 与 `/api/templates/click`，对应轮询与操作控件尚未同步。

沿用用户在 v1.11 确认的仅模板管理范围：保留模板新增、编辑、图片、删除、导入和导出，清理匹配与点击的失效入口及轮询。恢复实时匹配需单独评估并获得明确需求，不通过字段兼容或恢复旧引擎解决。

验收确认模板管理可用，页面不再发送已删除的匹配/点击请求，且不新增模板视频帧消费者。

## 验证与交付

本轮已完成统一构建、部署及页面/资源冒烟，不能代替三个遗留问题的修复验收，也不能代替前端 v0.7 的真机完整操作验收。

后续修复按实际改动执行类型检查、生产构建、必要的 Go 检查和浏览器验证；按当前部署页面核对分割线与图标，按请求和真实返回核对模板管理。提交、推送、标签与 GitHub Actions 运行状态分别记录。
