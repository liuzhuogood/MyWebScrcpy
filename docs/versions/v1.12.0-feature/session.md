## 会话

### 1. 用户

> 我还想增加一个实用功能，就是调整显示尺寸，这个移到设置里去，不用单独一个按钮了。然后，增加显示手机边框，支持常见的手机边框，手机边框的素材好像有个网站有。还有在录制时，可以选择：1. 是否录制边框 2. 是否录制点击反馈。先评估一下好不好做。

### 1. OpenCode

评估结论：

- **显示尺寸移入设置**：简单，前端闭环。现为「更多」菜单条目 + 独立 Dialog，改为放进设置面板即可，`usePlayer` 的 `displayScale/displayLabel/setDisplayScale/fitWindow` 已现成。
- **手机边框**：前端可行，中等难度。难点在素材适配（外壳素材有挖空屏幕区且比例固定，需逐机型配屏幕区元数据）和 fitCanvas 尺寸适配。
- **录制是否收录边框/点击反馈**：有架构冲突。当前录制为后端 `recording.go` 纯 Go mp4 封装器直接写 H.264/AAC，不经 ffmpeg；前端边框/点击反馈是 overlay canvas，不在 H.264 流里，后端录不到。

### 2. 用户

（问答确认）
> 录制实现方向：后端合成（需跨仓库）。
> 手机边框素材方案：CSS/SVG 绘制（推荐）。

### 2. OpenCode

确认后端仓库为 `MyWebScrcpy`（Go），定位录制实现 `internal/ws/recording.go`。关键发现：后端录制走 `newMP4RecordingMuxer`（纯 Go 封装），未引入 ffmpeg；触控消息经 WS 先到后端再转发 adb，故后端可见触控坐标，点击反馈有数据源；边框需前后端共享同一套几何参数。

给出分工：①② 前端可独立做；③ 录制 UI/传参前端可先做，后端合成为独立跨仓库任务。

### 3. 用户

> 先在原项目仓库建个版本四件套。

### 3. OpenCode

在 `MyWebScrcpy` 创建 `docs/versions/v1.12.0-feature/` 四件套（design/session/tasks/version）。
