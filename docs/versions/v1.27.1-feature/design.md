## 1. 版本目标

将任务运行页改为用户主动扫描工作目录，统一任务定义、进度和产出约定；新增总状态、总状态及决策两个接口；提供通用操作技能，让应用技能主要维护规则、Wiki 和模板。

执行、编排和定时仍由外部助手负责。服务负责观察任务文件、提供设备状态和操作能力。

## 2. 任务中心与工作目录

### 目录约定

默认根目录为 `~/.mywebscrcppy/tasks/`，其中 `~` 指运行服务的宿主机用户主目录，与启动目录、项目目录无关。启动时解析为绝对路径，可在系统设置中修改；不可写时明确报错，不回退到临时目录。外部助手直接写入该目录；远程执行需挂载到宿主机可读位置。

每次任务使用独立目录：

```text
~/.mywebscrcppy/tasks/<task-id>/
├── task.json          # 任务定义与产出约定
├── state.json         # 最新进度、业务结果
├── actions.jsonl      # 追加式操作记录
├── report.md          # 默认报告文件
├── logs/task.log      # 默认日志文件
├── screenshots/       # 默认截图目录
└── videos/            # 可选视频文件
```

- `task.json` 明确任务名称、设备 `serial`、目标、成功条件、执行期限、来源、所用技能绝对目录及产出约定。
- `state.json` 保存执行状态、阶段、进度、最近动作、最近结果、更新时间及结束原因。执行状态包括待执行、运行中、暂停、成功、失败、取消。
- 状态文件采用临时文件加原子替换；操作日志追加写入。运行中的任务中断后从当前目录和实际设备状态继续。
- 工作目录持久保留；取消强制临时目录、结束自动清理和默认录屏要求。

### 产出约定

任务开始前，在 `task.json.outputs` 中逐项声明产出。每项包含标识、类别、格式、相对路径和是否必需；目录产出还须声明允许的文件类型。

| 产出类别 | 默认路径 | 格式 | 默认要求 |
|---|---|---|---|
| 报告文件 | `report.md` | Markdown | 必需 |
| 日志文件 | `logs/task.log` | UTF-8 文本 | 必需 |
| 截图目录 | `screenshots/` | PNG/JPEG | 可选 |
| 视频文件 | `videos/recording.mp4` | MP4 | 可选 |

- 路径可以按任务调整，但必须位于本次任务目录内。多个报告或视频分别声明，避免依赖命名猜测。
- 目录产出展示实际文件列表；声明为必需时至少包含一个有效文件。日志允许为空，报告与媒体文件不能以空文件满足要求。
- 任务中心展示报告、日志、截图缩略图和视频播放/下载入口，全部依据产出声明读取。
- **业务结果与产出完整性分别记录**。例如业务成功但缺少必需视频，应显示“业务成功、产出不完整”；整体完成需要两者均满足。
- 不从报告正文提取 JSON 或猜测截图、视频路径；报告中的声明不能替代文件检查。

### 扫描与页面

- 用户点击“扫描刷新”时调用 `POST /api/task-runs/scan`，扫描当前根目录并重建内存索引，返回扫描时间、任务数量及异常摘要；扫描期间禁用重复提交。
- 不做启动扫描、目录监听、定时补扫或前端自动轮询。列表、筛选和翻页只查询最近一次扫描结果，页面显示扫描时间。
- 首次启动或服务重启后等待用户扫描；切换根目录时清空旧索引，等待再次扫描。任务文件变化及执行端均不自动触发扫描。
- 打开详情只读取指定任务文件，详情通过用户手动刷新更新，不扫描整个根目录。
- 保留 `/tasks`，支持设备、状态、来源筛选及任务详情；详情展示进度、报告、操作记录和实际产出。
- 文件损坏、写入未完成、目录不可读单独标明，不影响其他任务。长期未更新只表示信息陈旧，不推断进程死亡或任务失败。
- 移除任务注册、心跳、日志上传、结束上报接口及 `TaskReporter`；保留只读查询路径并更新响应类型。
- 升级时通过定向、幂等的数据库结构升级，直接删除旧任务表、任务记录和任务上报日志，不迁移、不保留历史查询；移除对应数据库读写方法，新数据库不再创建旧任务表。
- 保留设备数据、系统配置、操作日志、模板及数据库外用户文件。

## 3. 统一设备状态与技能模板

### 访问接口

取消等级参数，按是否需要 AI 决策分为两个接口，共用同一采集服务：

```text
GET  /api/device-state/{serial}           # 总状态
POST /api/device-state/{serial}/decision  # 总状态及决策
```

两个接口默认返回 JSON；请求头 `Accept: text/html` 时返回简单 HTML，不另设 HTML 路由。总状态的可选 `task_id`、`template_ids` 使用查询参数；决策请求通过 JSON 请求体传入相同选项及可选 `goal`。

| 接口 | 返回内容 |
|---|---|
| 总状态 | 设备状态、页面信息、本轮截图、UI XML、OCR、模板匹配，以及关联任务的目标、进度与产出摘要；不调用决策模型 |
| 总状态及决策 | 完整总状态，加 AI 对当前页面、任务进展和下一步操作的判断，包含依据及不确定项 |

- HTML 使用服务端模板，展示必要内容与手动刷新入口；默认不自动刷新。
- 每次请求只采集一轮状态，决策接口直接使用本轮结果调用模型，不再次采集。两个接口均返回截图，取消等级和按等级裁剪内容的逻辑。
- 自动关联依据最近一次手动扫描的任务索引：同设备唯一运行任务时关联，多个运行任务且未指定 `task_id` 时返回关联冲突，并注明索引扫描时间。无运行任务时仍可读取设备状态。
- 显式指定 `task_id` 时直接读取该任务目录并验证设备一致，不触发根目录扫描。
- 每项观测记录来源、采集时间及成功、失败或不可用状态；截图、OCR、匹配和 AI 结果绑定同一观测标识。
- 复用现有采集、OCR、匹配和设备并发控制能力。采集前后核对页面上下文，变化时标记观测不稳定，不冒充原子快照。
- 部分采集失败仍返回已取得内容；空识别结果、依赖不可用和请求失败明确区分。

### 三类模板来源

默认匹配：

1. 全局启用模板。
2. 当前设备启用模板。
3. 关联任务所用技能中的启用模板。

技能模板直接读取 `task.json` 声明的技能目录，统一放在：

```text
<skill-dir>/templates/<template-id>/
├── meta.json
└── template.png
```

复用现有模板元数据与匹配参数，不导入全局模板库。匹配结果带来源、技能标识及模板标识；同名模板分别保留，不相互覆盖。

技能模板变化在下一轮观测生效，每次记录实际读取内容的摘要。目录或模板损坏明确报错，不使用旧缓存伪装最新结果。

### 总状态及决策

- 系统设置的服务区域新增完整 Chat Completions 地址、模型名、密钥和超时配置；密钥不回传明文、不写入日志。
- 发送本轮截图及必要页面、任务上下文，返回页面摘要、可见控件与弹层、任务进展判断，以及下一步建议、依据和不确定项；决策结果不触发设备操作。
- 请求提供 `goal` 时以其作为本轮决策目标，否则使用关联任务的目标；两者均缺失时仅分析当前页面，明确缺少任务目标，不推测用户意图。
- 决策结果绑定本轮观测标识，仅供执行方参考；动作执行前须核对观察是否仍有效，动作后重新观察并验证业务结果。
- 图片使用 Base64 data URL；协议依据[官方视觉输入文档](https://developers.openai.com/api/docs/guides/images-vision/)。
- 未配置、鉴权失败、超时或响应不合法时，保留完整总状态，明确标记决策不可用并显示原因，不虚构建议或成功结果。
- 基础采集预算 20 秒，AI 预算 30 秒；同设备串行采集，AI 全局最多并发 2 个，超额明确拒绝，不形成无限队列。请求取消时释放资源。

## 4. 通用操作技能与应用技能

新增 `my-scrcpy-common`，提供规则、Wiki 和共享操作脚本，并加入技能市场。

| 通用操作 | 行为与验证 |
|---|---|
| 观察页面 | 读取总状态；需要下一步建议时请求总状态及决策 |
| 看视频 | 按配置随机停留，再执行拟人化上滑；默认间隔 5～15 秒，受总时限约束，按检查点交回助手判断页面 |
| 尝试返回 | 获取前后观测，发送 `KEYCODE_ESCAPE`（111），判断页面或弹层是否变化 |
| Android 返回 | 单独提供 `KEYCODE_BACK`（4），与 ESC 区分 |
| 打开 APP | 使用已确认包名启动，验证实际前台包名和页面 |
| 重启 APP | 对明确目标执行停止、重新启动，再验证实际状态 |

像素变化只能作为辅助证据；视频播放变化不能证明返回成功。无法确认时记录“未知”，由助手继续观察。共享脚本负责通用动作和采集，应用业务判断留在规则与助手决策中。

应用技能统一采用：

```text
<skill>/
├── SKILL.md
├── rules/
├── wiki/
└── templates/     # 按需
```

- 快手、钉钉及市场中的应用技能移除专用业务脚本、代码生成要求和专用 dryrun 流程；通用请求、观察和操作能力集中到共享技能。
- `rules/` 写目标、页面判断、业务边界和成功条件；`wiki/` 保存经验证的页面知识、异常及恢复经验。
- 同步更新基础使用技能、安卓技能规范和任务启动提示词，取消强制上报、强制录屏和强制生成脚本的旧要求。
- 仓库技能与市场包同步更新；已安装到用户目录的技能通过现有安装流程升级，继续保护用户修改。微信保持仅读取、草拟的既有边界。

## 5. 实施顺序与验收

实施顺序为：任务文件与产出契约、旧任务表清理 → 手动扫描及任务页 → 总状态与技能模板 → 总状态及决策 → 通用技能及应用技能精简。

验收覆盖：

- 创建、更新、暂停、结束、恢复任务，以及服务重启后通过用户扫描重新发现。
- 启动、进入页面、等待和文件变化均不自行扫描；手动扫描、重复点击、根目录切换及详情手动刷新行为符合约定。
- 旧任务表及记录确实删除，重复升级正常，其他设备数据、配置及操作日志完整保留。
- 文件半写入、损坏、目录删除、根目录切换、产出缺失和路径越界。
- 报告、日志、截图、视频的真实读取、预览与下载；产出不完整不能展示为整体完成。
- 总状态不调用决策模型；决策接口只采集一轮状态并绑定同一观测标识；两个接口的 JSON 与 HTML 信息一致，不保留等级路由。
- 设备离线、页面切换、单项失败、多任务关联冲突，以及有目标、无目标和决策结果不自动执行的场景。
- 三类模板同时匹配、同名隔离、技能模板修改及损坏。
- AI 鉴权失败、超时、取消、并发限制及密钥脱敏。
- 真机验证随机上滑、ESC 前后判断、打开及重启 APP；实际浏览器验证任务详情和媒体交互。
- 更新 OpenAPI、SDK、术语字典、技能包及版本设计记录；检查旧上报入口和失效引用完整移除。
