# v1.17.0-feature 版本说明：Markdown 脚本内嵌 Cron 调度器与排期执行系统

更新日期：2026-10-11。  
**当前状态：实施完成，全链路测试通过，已在 10.0.0.6 生产环境验证 Cron 自动触发与排他保护闭环。**

---

## 1. 版本背景与目标

在 v1.16.0 中，系统已成功落地了 Markdown 脚本的 SQLite 持久化、正则解析、版本一致性缓存比对，以及基于真实系统进程 PID 的任务管理器与设备排他锁机制。然而当前脚本的执行主要依赖用户在 Web 界面上手动点击「立即运行」。

本版本旨在构建**全自动、无人值守的轻量级内嵌 Cron 调度系统**：

1. **内嵌式 Cron 调度引擎**：基于成熟的 Go 标准库 `robfig/cron/v3`，将调度器内嵌进 `mywebscrcpy` 服务中，无需依赖外部 Linux crontab 或第三方分布式任务平台。
2. **热重载（Hot-Reload）**：脚本的新建、修改、删除或启用开关切换时，调度器动态更新 Cron 注册池，无需重启后台服务。
3. **天然排他性保护（SkipIfStillRunning）**：定时时刻到达时，必须经由任务管理器检查目标设备占用状态。若设备正忙，坚决不并发打架，自动跳过并记录审计日志。
4. **编译与版本自动护航**：触发时自动检测 Markdown 当前提取版本与已编译稳定 Python 代码版本，若版本未编译则自动先转译再执行。
5. **前端排期透视与控制**：在 Web 工作台直观展示下一次执行时刻倒计时，并提供定时调度开关与状态观测。

---

## 2. 核心架构与模块规划

1. **调度服务核心（`internal/scheduler/`）**：
   - `scheduler.go`：管理 `cron.Cron` 实例，负责启动、停止、全量加载、单脚本热重载；
   - 调度执行器：封装单次触发流程（版本检查 ➔ 目标设备寻址 ➔ 设备锁校验 ➔ 启动任务管理器 ➔ 记录触发状态）。
2. **数据访问与模型扩展（`internal/db/`）**：
   - 增加 `last_run_at`、`last_run_status` 等运行轨迹字段记录；
   - 支持脚本定时开关的单独更新。
3. **HTTP API 端点（`internal/scheduler/handlers.go`）**：
   - `GET /api/scheduler/status`：获取当前所有正在排期的任务及下一次执行时间戳；
   - `POST /api/md-scripts/{id}/toggle-schedule`：快速切换脚本的定时调度开关。
4. **前端看板与交互（`frontend/src/`）**：
   - 在指标区计算展示「下一次触发倒计时」；
   - 任务管理器弹窗增加「定时排期」概览列表。

---

## 3. 验收标准

1. **单元测试**：`internal/scheduler/` 覆盖标准 Cron 表达式解析、热重载添加/移除、多设备互斥跳过测试。
2. **全流程自动化验证**：
   - 配置 `*/1 * * * *`（每分钟执行一次），验证到点自动触发执行并分配系统 PID；
   - 构造设备占用场景，验证到点自动拦截并记录 `skipped` 状态，不损坏正在执行的任务；
   - 界面上动态修改 Cron 周期，验证无缝生效，无需重启服务。
3. **生产环境部署**：全量测试与构建通过后，发布部署至 `10.0.0.6` 验证。
