## 1. 版本背景与目标

目前系统具备了设备投屏、ADB 单次命令、文件管理及基于 Python 客户端的模板匹配能力，但缺乏面向复杂业务的「自动化流程编排与持续执行」体系。  
本版本旨在构建一套**直观、轻量、高稳定性的 Markdown 驱动自动化引擎**：

1. **Markdown 规范驱动**：通过标准 YAML Front-Matter 声明版本号、Cron 定时周期、目标设备与超时时间；通过文字组织 ADB 流程，通过图片标记（`template://<id>`）组织 OpenCV 模板匹配。
2. **服务端 SQLite 纯集中持久化**：所有脚本与元数据纯存放在服务端数据库，避免手机端同步造成的时间戳漂移与图片资产丢失。
3. **版本比对与防重复生成**：优先通过正则提取 `version`；提取不到时回退为修改时间戳；当 Markdown 版本一致时直接复用稳定 Python 脚本，避免无谓的重复编译。
4. **Pi 三环境解耦流水线**：
   - **Pi 1 (Doc Agent)**：负责以对话形式自动生成与就地调整 Markdown 文档；
   - **Pi 2 (Code Agent)**：负责将确认版本的 Markdown 转换为稳态 Python 脚本；
   - **Pi 3 (Runner Agent)**：负责托管执行守护、日志流转与异常兜底。
5. **基于任务管理器 PID 的设备排他锁**：
   - 建立任务管理器，每台手机同一时间仅允许运行一个任务；
   - 任务启动时在任务管理器注册系统进程真实 PID 并追踪生命周期；
   - 前端支持随时查看活跃任务与一键强杀（kill）结束任务；
   - 其他脚本执行前直接查询任务管理器判断目标设备是否被占用，天然实现设备互斥锁。
6. **Web 前端四栏沉浸式工作台**：
   - AI 文档助手对话栏（生成/调整）
   - Markdown 源码编辑栏
   - 渲染预览与指标提取栏
   - 稳定 Python 产物与任务管理器控制栏

## 3. 验收标准与交付物

1. **数据库迁移**：SQLite 自动创建 `markdown_scripts` 与 `running_tasks` 表。
2. **API 接口**：提供脚本 CRUD、正则解析提取、缓存检查、编译触发、任务管理器列表与任务强杀接口。
3. **任务管理与锁机制**：实测同一设备无法同时启动两个任务，任务管理器强杀进程后锁即刻释放。
4. **前端交互**：在主界面提供脚本管理与任务管理器面板，对话生成、源码编辑、渲染预览与 Python 产物联动自如。
5. **构建全绿**：`pnpm run build`、`go test ./...` 与 `scripts/build.sh` 全流程通过。
