# v1.3.1-fix 会话记录

> 本版本是 v1.3.0 的补丁版本，用于纠正文件管理对象和令牌功能范围。

## 问题现象

用户反馈：

1. 1.3.0 将文件管理实现成了服务端文件系统管理；实际需求是管理手机上的文件。
2. 前期产品要保持简单，不需要令牌功能；当前 UI 中仍有令牌按钮、令牌弹窗和相关提示。
3. 文件管理需要支持多台手机，但独立文件管理入口无法天然确定当前操作的是哪台手机。
4. 横竖屏按钮持续表现异常，初步判断可能不是投屏控制协议故障，而是当前手机前台应用锁定了屏幕方向，不支持跟随设备旋转。

## 根因

1.3.0 设计和实现阶段错误地把文件来源确认成服务端 `FILES_DIR` 本地目录，并据此加入了 `FILES_TOKEN` Bearer 鉴权及前端令牌输入流程，偏离了手机文件管理需求。横竖屏问题还需要区分“设备旋转控制”和“前台应用是否允许改变方向”：投屏工具本身不能直接修改目标应用的方向策略。

## 修复改动

- 将文件管理入口放入投屏页面的“更多”菜单；用户进入投屏页面时已经选定手机，点击“文件管理”后直接管理当前手机的文件。
- 以弹窗形式承载文件管理，不再依赖独立页面入口或让用户额外选择手机；关闭弹窗后返回当前投屏页面。
- 修复弹窗定位：文件管理弹窗在投屏页面视口内水平、垂直居中显示，窄屏下保持适当边距并支持内容滚动，不再固定出现在左上角。
- 核对横竖屏兼容性：使用支持方向变化的应用验证投屏旋转链路；对于锁定方向的应用，明确提示其应用策略限制，不把应用拒绝旋转误判为投屏按钮故障。
- 如产品确实要求强制旋转锁定方向的应用，另行确认 Android 版本、目标应用和强制忽略方向请求的兼容策略后再实现，不直接引入未经确认的系统设置修改。
- 将文件管理的数据来源和操作对象改为当前选定手机的文件存储，不再以服务器本地目录作为用户文件根目录。
- 移除令牌功能设计：删除文件管理页面上的令牌按钮、令牌弹窗、令牌输入提示和相关会话存储逻辑。
- 同步移除文件管理接口对 `FILES_TOKEN` / Bearer 令牌的依赖，保持前期单用户、简单访问流程。
- 清理文档、配置说明和测试中与服务端文件目录、令牌鉴权相关且不再适用的表述与用例。

### 已完成

- 将文件管理器从服务端本地目录改为通过 ADB 操作当前请求 `serial` 对应手机的 `/storage/emulated/0` 共享存储。
- 重写文件 API 的列表、搜索、分页、容量读取、上传、下载、新建文件夹、移动、重命名、删除与撤销；路径仍做服务端清理，手机端回收站目录不暴露给列表和搜索。
- 上传先写临时文件再执行 `adb push`，临时文件在请求结束后清理；删除撤销使用手机端隐藏回收站。
- 移除 `FILES_DIR`、`FILES_TOKEN`、Bearer 鉴权和服务端磁盘存储实现，保留 `FILES_MAX_UPLOAD_BYTES` 作为上传大小限制。
- 从设备列表页移除独立文件管理入口；投屏页“更多”菜单新增文件管理按钮，以当前 `serial` 打开居中的弹窗和 iframe，移动端保留边距与滚动空间。
- 横竖屏按钮增加方向锁定提示：请求后若视频尺寸未变化，提示“应用可能锁定方向”，不将前台应用方向策略直接判断为投屏故障。
- 同步更新中英文 README 与生产环境资产说明。
