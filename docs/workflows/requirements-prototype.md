# 需求原型工作流

状态：可执行
用途：收集需求、验证首页设备卡片手机拟物设计，把需求资料与原型合入主干，阶段到此结束。
输入：
- 目标项目：`/Users/liuzhuo/code/MyWebScrcpy`
- 主题：`device-phone-card`（首页设备卡片手机拟物重构）
- 原型分支：`codex/prototype/device-phone-card`
- 原型目录：`prototypes/cases/device-phone-card-v1`
- 预览命令：`pnpm --dir frontend proto`（端口 5174）
- 检查与构建命令：`pnpm --dir frontend proto:check`、`pnpm --dir frontend proto:build`
- 隔离复核：`pnpm --dir frontend build`（确保原型不污染正式产物 `web/dist/`）

| 编号 | 操作 | 通过条件 | 失败处理 |
| --- | --- | --- | --- |
| RP1 | 用 VLog 收集需求，必要时 grilling | 目标、范围与原型场景清楚；已确认需求和待定项分开记录 | 澄清影响原型的关键取舍（如“圆形”的形态歧义与排版空间利用率） |
| RP2 | 用 lz-prototype 生成或迭代原型 | 复用项目组件与主题，独立入口可运行，模拟数据无真实业务副作用；支持方案 A (圆润拟物) 与方案 B (圆形表盘) | 补齐预览条件，范围内修正 |
| RP3 | 实测原型、保存截图与结论，完成源码交接并执行项目检查 | 需求场景与原型对应，必要交互及完整校验通过；选定方案的源码目录、入口、组件与状态已记录；正式构建未包含原型 | 返回 RP2 修正 |
| RP4 | 提交需求文档、原型源码、源码交接和验证证据到原型分支 | 精确范围提交完成，记录完整 SHA；工作区干净 | 按 Git 规则处理，不夹带其他改动 |
| RP5 | 将原型成果合入主干，复测合并结果后完成合并提交 | 主干包含 RP4 提交，资料、源码交接、预览和构建隔离验证通过 | 冲突或失败保留现场，按授权合入 |
