## 需求背景与核心诉求

在自动化脚本开发与托管执行体系中，单纯的 Python 执行日志在排查偶发故障、时序偏差或视觉未命中时存在局限。  
为了实现**可溯源、可视化的执行结果报告**，远期需要为「稳定化脚本生成」及「托管执行」增加全链路的日志、截图与视频产物捕获能力。

---

## 1. 核心需求要点

1. **基础产物捕获（日志与关键步骤截图）**：
   - 生成的稳定 Python 脚本需内置标准化日志输出（结构化 JSON / 标准流日志）；
   - 关键操作节点（如应用打开后、模板匹配前后、点击动作发生时、出现异常失败时）自动触发设备截屏，并留存图片。

2. **Markdown 显式声明产物捕获约定**：
   - 支持在 Markdown 文档头部 YAML 或正文步骤中通过正则直观声明截图/录像需求：
     ```markdown
     ---
     name: 自动化操作
     artifacts:
       screenshot_on_step: true   # 关键步骤自动截图
       screenshot_on_fail: true   # 失败自动截图保全现场
       record_video: true         # 全程录屏
       video_quality: "medium"    # 视频清晰度
     ---

     # 步骤
     - 点击登录按钮
     - [捕获截图: 登录后主页]      # 步骤级显式截图指令
     - [捕获录屏: 30s]            # 片段级显式录制指令
     ```

3. **完整执行产物归档打包 (Artifact Bundle)**：
   - 单次脚本执行结束后，自动将本次运行生成的产物组织为统一产物包：
     - `execution.log`（完整执行日志）
     - `screenshots/`（步骤截图、模板比对特征图、失败现场截图）
     - `recordings/`（执行全程或片段 MP4 视频录像）
     - `summary.json`（执行概览：耗时、步骤成功率、退出码、生成的产物清单）
   - Web 界面提供「历史执行产物查看」面板，支持在线回看日志、预览每一步截图以及播放执行录屏。

---

## 2. 架构与依赖设计考量（Pi 三环境中的职责）

- **Pi 环境 1 (Doc Agent)**：
  - 负责在 Markdown 编写和对话调整过程中，理解用户的截图/录制诉求，生成标准的 YAML 声明或步骤宏标记。
- **Pi 环境 2 (Code Agent)**：
  - 识别 Markdown 中的产物标记，在编译生成 Python 脚本时，注入产物采集插桩代码（如 `artifact_manager.take_screenshot("step_1")`、`dev.start_record()`）。
- **Pi 环境 3 (Host Runner)**：
  - 在托管执行期管理产物输出目录（如 `data/artifacts/<run_id>/`），执行完毕后打包归档并写入 SQLite，通知前端刷新产物报告。
