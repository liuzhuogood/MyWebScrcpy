# 视觉决策任务启动提示词

记录日期：2026-10-17  
状态：模板草案，尚未通过新的实际任务验证。使用前替换花括号中的内容。

相关方向见 [APP 视觉决策任务：最新想法与待办](visual-decision-automation-notes.md)。本模板不表示统一状态接口已经实现。

```text
请通过观察当前界面、判断状态并操作设备，完成以下任务。

任务目标：{要完成的业务目标}
成功条件：{可以通过页面或业务结果核验的完成条件}
服务地址：{已确认的 MyWebScrcpy 服务根地址}
设备：{已确认的 serial}
执行时限：{总时长或截止时间}
本机工作目录：{执行所在机器上的绝对路径}
本次任务目录：{上述工作目录下的独立子目录绝对路径}
决策模型：{当前具备视觉能力的助手，或已确认可用的模型}
证据保存频率：{例如长时观看每 60 秒最多保存一张截图}
允许执行的操作与边界：{本次任务允许的业务操作}

执行方式：
1. 先确认服务、设备、工作目录、任务目标与完成条件。使用 API 前，核对当前源码、实时 Schema 或官方文档，不猜接口、参数与响应字段。
2. 不为目标 APP 编写堆叠页面分支的专用脚本。使用通用观察与操作工具，由视觉决策方结合当前画面、任务目标和最近操作选择下一步动作。
3. 如果已有统一状态接口，先核对它的实际定义，再读取界面、APP、设备与本地任务状态。如果尚未实现，则通过已核实的现有能力汇总所需状态，明确各项来源和采集时间，不虚构接口。
4. 每轮执行「观察当前状态 → 判断下一步 → 执行一次动作 → 核对实际结果」。OCR、UI XML 和模板匹配可辅助理解与定位；页面变化后重新观察，不使用过期定位继续点击。
5. 理解按钮与任务的关系，区分广告、奖励、关闭入口及其他跳转。证据不足或目标不唯一时，重新观察或记录「无法确定」，不盲点，不因按钮写着「领取」就认定属于当前任务。
6. 区分操作已发送、页面显示成功与业务结果已确认。例如领取提示和余额到账分别核验。动作结果未知时先检查当前状态，不直接重复动作。
7. 所有任务记录保存在本次任务目录内，包括目标、当前进度、最近动作、观察结果、异常、必要截图和最终报告。更新最新状态并保留追加式操作日志，便于中断后从实际状态继续。
8. 不向 MyWebScrcpy 任务运行页上报状态、心跳、日志或结果，不创建 TaskReporter。工作目录使用本机已确认的目录，不默认切换到临时执行目录。若所加载技能存在相反约定，以本提示词明确的本地记录要求为准。
9. 截图按指定频率保存，避免大量重复画面。需要重新观察时可以读取新画面，不必每次都另存截图。录像按本次任务的明确需求决定，不默认开启长时间录像。
10. 等待与重试设置期限；失败保留现场与原因。遇到无法判断的状态时说明缺少的证据，不能将未知结果记成成功。

结束时请给出：实际完成结果、关键前后变化、尚未确认的事项，以及本地记录和证据路径。
```
