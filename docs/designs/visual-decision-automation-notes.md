# APP 视觉决策任务：最新想法与待办

记录日期：2026-10-17  
状态：需求与学习方向记录，尚未实施接口、调整现有技能或选定模型。

## 用户最新感受

1. 不要为「快手」类 APP 写脚本，因为脚本太难维护。
2. 要增加一个统一状态接口，返回界面、APP、任务状态等所有决策相关状态，方便决策。
3. 要找一下小的决策、识图模型。
4. 不再上报任务状态，任务就放在当前机器的工作目录。
5. 写一个模板提示词，方便启动任务。

## 1. 从 APP 专用脚本转向视觉决策

快手这类 APP 的广告、活动、弹窗、按钮和页面布局变化频繁。依靠模板匹配、OCR 文本和页面分支编写业务脚本，需要不断补规则，维护成本过高。

新的方向是由模型结合当前画面、任务目标和最近操作选择下一步动作，不再为每种页面变化编写 APP 专用规则脚本。截图、OCR、点击、滑动、等待、返回等通用工具可以复用。

OCR 和模板匹配保留为可选的观察与定位工具。模型需要理解按钮与任务的关系，并在操作后核对结果。例如「发现领取按钮」「已点击」「出现领取成功提示」「金币实际到账」应分别记录，不能互相替代。

## 2. 增加统一状态接口

目标是让决策方通过一个读取入口取得本轮决策所需的状态，减少分散调用和自行拼接。以下是需求范围，不是已经存在的 API 契约。

| 状态范围 | 需要提供的内容 |
|---|---|
| 设备与界面 | 设备标识、连接状态、当前截图、画面尺寸、旋转、采集时间和画面关联信息 |
| APP 与页面 | 前台包名、Activity、焦点窗口；需要时提供 OCR、UI XML 和候选控件 |
| 本地任务 | 目标、当前阶段、已用与剩余时间、最近动作、最近结果、完成条件和已确认进度 |
| 观察有效性 | 各项来源、时间、是否采集成功、是否过期、是否在采集过程中发生页面切换 |
| 异常与不确定性 | 设备不可达、部分状态缺失、页面冲突、目标不唯一，以及需要重新观察的原因 |

设计时需要解决两个问题：

- 多项状态可能在不同时间采集，应明确关联与有效性，不能把聚合结果默认当成原子快照。缺失或未知的状态应明确标记。
- 设备与 APP 状态来自服务，本地任务进度来自当前机器的工作目录。统一入口如何关联两者需要后续设计，不能默认服务端已经知道任务进度，也不能以恢复任务上报作为前提。

接口路径、请求参数、响应字段、采集开销和部分失败语义均待设计，不在本记录中预设。

## 3. 寻找小型决策与识图模型

学习目标是训练一个能观察界面、识别按钮、理解点击意图并选择动作的模型。研究时分别评估页面理解、控件定位、动作选择和操作后结果判断。

当前讨论中的候选线索如下，均未完成本场景选型与实测：

| 候选 | 研究方向 |
|---|---|
| [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B) | 小型通用视觉模型，研究领域数据微调 |
| [ShowUI-2B](https://huggingface.co/showlab/ShowUI-2B) | GUI 目标定位与动作输出 |
| [UI-TARS-2B-SFT](https://huggingface.co/ByteDance-Seed/UI-TARS-2B-SFT) | 连续界面观察与操作决策 |
| [NeoHorse-Jev-4B](https://huggingface.co/TokenRhythm/NeoHorse-Jev-4B) | 带图片输入的结构化决策 |
| [SmolVLM2-500M](https://huggingface.co/HuggingFaceTB/SmolVLM2-500M-Video-Instruct) | 更小规模的视觉理解与训练实验 |
| [Jev](https://typesafe.ai/blog/jev-1-14) | 体验结构化决策与实验性图片能力；与可下载、可自行训练的模型分开评估 |

「是否为广告」「是否存在诱导点击」「按钮可能导致什么结果」需要单独准备样本和评测。界面证据不足时允许模型输出「无法确定」；部分行为需要结合操作前后的页面变化判断。

先用现成模型进行离线截图测试，再根据具体错误收集数据、标注与微调。数据应覆盖不同页面、弹窗和失败场景，大量重复的视频画面不能替代决策样本。模型规模与训练方式待确认硬件后选择。

## 4. 任务记录放在本机工作目录

任务执行采用本地工作目录记录约定，任务定义、进度、操作记录、截图和结果直接保存在执行所在机器的工作目录内。

建议每次任务使用工作目录下的独立子目录，保存任务说明、最新状态、追加式操作日志、必要截图和最终结果。该目录应支持查看进度及中断后继续；未知结果如实记录，不将异常直接标成完成。

## 5. 提供启动任务的模板提示词

可复制的模板见 [视觉决策任务启动提示词](visual-decision-task-prompt.md)。模板包含目标、设备、工作目录、完成条件、观察与决策方式，以及本地记录约定。
