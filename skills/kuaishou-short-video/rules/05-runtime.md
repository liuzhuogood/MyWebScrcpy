# 快手运行时与设备状态规则

本文档定义快手短视频执行过程中的只读观测、稳定性判断与证据留存规范。

## 1. 设备观测与稳定性核对

1. **只读状态采集**：
   - 在执行任何关键动作前，调用 `GET /api/device-state/{serial}` 读取设备总状态。
   - 检查 `context_stable` 是否为 true。若在采集期间页面 Activity 或顶层窗口发生剧烈变动，说明处于过渡动画或页面切换中，应等待 0.5 秒重新采集（最多重试 3 次）。
   - 提取最新 `observation_id`，所有基于此观测做出的判断与动作均绑定该观测标识。

2. **多模态页面理解**：
   - **页面信息 (page_info)**：验证 `package_name` 为 `com.kuaishou.nebula`，记录当前 Activity。
   - **UI XML**：解析控件层次与可点击节点 bounds，计算动态中心点坐标。
   - **OCR 结果**：提取“连续签到”、“已签到”、“立即领取”、“恭喜获得”等关键文本。
   - **模板匹配**：对于纯图标无文本按钮（如关闭叉号、金币小挂件），优先通过模板匹配定位坐标与置信度。

## 2. 证据与产出留存

1. **关键证据截图**：
   - 签到前主页、点击签到后弹窗、看视频前后金币变动分别保存现场截图至 `screenshots/` 目录。
   - 遇到无法处理的异常阻碍（如账号风控、滑块验证码、密码输入）时，必须留存当轮截图与 XML 作为失败证据。

2. **日志记录**：
   - 将步骤时间、动作名称、耗时及响应结果追加写入任务目录下的 `logs/task.log`。
   - 严禁将密码、Token 或其他敏感用户数据写入日志文件。
