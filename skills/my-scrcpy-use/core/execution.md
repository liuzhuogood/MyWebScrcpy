# 自动化任务执行规范

1. 执行前读取目标模块，按[环境规范](env.md)注册环境并使用规范的任务工作目录 `~/.mywebscrcppy/tasks/<task-id>/`；确认设备连接、前置条件、执行时限与成功标准，所有运行产物均保存在该目录内。工作目录持久保留，取消强制临时目录与结束自动清理要求。
2. 操作优先使用 Python SDK `pip3 install mywebscrcpy-sdk` 公开接口；未封装的能力按[入口规则](../SKILL.md)或共享操作技能 `my-scrcpy-common` 调用服务端 API。仍无法满足要求时才使用 ADB，并记录原因；接口报错先排查，不用 ADB 绕过错误。
3. 每一步操作前立即打印日志，包含步骤编号、操作内容和目标；操作后记录结果与耗时，日志不含凭据或敏感输入。
4. 捕获脚本 stdout、stderr 和异常堆栈，关联失败步骤；保留原始报错，不吞异常或仅输出“失败”。
5. 需要核对页面、定位或留证时，在该步操作前通过 SDK 或总状态接口获取当前画面并保存截图；异常时补存现场截图，记录文件路径。截图失败单独记录，不覆盖原始错误。
6. 根据任务产出声明按需录屏；仅在产出明确声明了可选视频时启动录屏，不强制要求默认录屏。录屏异常明确记录。
7. 执行报错后保存现场并接管任务，可结合 XML、OCR 或视觉判断，在授权范围内从当前状态继续。动作结果不明时先查实际状态，不盲目重发或从头重跑。
8. 接管默认最多 3 轮，总耗时不超过任务剩余期限；同一错误无新线索、连续无进展，或遇到设备不可达、密码、人脸、验证码等明显阻塞时立即退出，保留原因与证据。
9. 接管成功后，将经验证的识别、定位、等待或恢复经验更新到规则与 Wiki 知识库，不固化临时绝对坐标。未完成更新或验证时如实报告。
10. 记录最终结果并生成符合产出约定的报告，以实际页面或业务结果判断成功。任务报告说明结果、接管方式、阻塞原因和证据链接。
11. 任务数据保存在任务工作目录内；报告引用的截图、视频和日志按声明保留，不向目录外转存。
