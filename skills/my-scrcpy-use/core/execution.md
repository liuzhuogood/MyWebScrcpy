# 自动化任务执行规范

1. 执行前读取目标模块，按[环境规范](env.md)注册环境并创建独立临时执行目录；确认设备连接、前置条件、执行时限与成功标准，所有运行产物均保存在该目录内。
2. 操作优先使用 Pyhon SDK `pip3 install mywebscrcpy-sdk`公开接口；未封装的能力按[入口规则](../SKILL.md)调用服务端 API。仍无法满足要求时才使用 ADB，并记录原因；接口报错先排查，不用 ADB 绕过错误。
3. 每一步操作前立即打印日志，包含步骤编号、操作内容和目标；操作后记录结果与耗时，日志不含凭据或敏感输入。
4. 捕获脚本 stdout、stderr 和异常堆栈，关联失败步骤；保留原始报错，不吞异常或仅输出“失败”。
5. 需要核对页面、定位或留证时，在该步操作前通过 SDK 获取当前画面并保存截图；异常时补存现场截图，记录文件路径。截图失败单独记录，不覆盖原始错误。
6. 业务操作前通过 SDK 录屏接口启动录屏；当前 SDK 未封装时，按实时 OpenAPI 调用服务端录屏接口。记录本次录屏标识，在 `finally` 中停止本次录屏、保存并检查视频；录屏异常明确记录。
7. 执行报错后保存现场并接管任务，可结合 XML、OCR 或视觉判断，在授权范围内从当前状态继续。动作结果不明时先查实际状态，不盲目重发或从头重跑。
8. 接管默认最多 3 轮，总耗时不超过任务剩余期限；同一错误无新线索、连续无进展，或遇到设备不可达、密码、人脸、验证码等明显阻塞时立即退出，保留原因与证据。
9. 接管成功后，将经验证的识别、定位、等待或恢复经验更新到该任务脚本，不固化临时坐标；由规则生成的脚本先更新规则源再生成，并验证修改。未完成更新或验证时如实报告。
10. 通过 [TaskReporter](task-reporting.md) 上报日志及最终结果，以实际页面或业务结果判断成功。任务报告总计不超过 **200 字**，说明结果、接管方式、脚本更新及验证情况、阻塞原因和证据链接。
11. 无论成功、失败或取消，收尾时清理本次临时执行目录；报告引用的截图、视频和排障日志需要保留时仍留在该目录，清理其余临时文件，不向目录外转存。仅删除本次生成的文件，不删除用户原有文件；清理失败记录路径与原因，不覆盖任务原始结果。
